## 密码安全传输升级

### 背景和目标

- 背景：传统接口直接传递明文密码，存在被窃听风险。
- 目标：
  - 在传输阶段隐藏用户原始密码，防止被中间人窃听。
  - 保持后端密码存储机制的安全性（Argon2）。
  - 为未来功能扩展提供标准化的实现方案。

### 项目范围

- **包含**：
  - Web 客户端注册、登录、重置密码流程。
  - 认证服务接口 `POST /auth/register`、`POST /auth/login`、`POST /auth/password/reset`。
  - 环境变量管理和部署流程。
- **不包含**：
  - 移动客户端升级。
  - 第三方 OAuth 认证逻辑。

### 干系人

| 角色 | 职责 |
| --- | --- |
| 产品经理 | 定义需求、协调资源 |
| 前端开发 | 实现密码哈希、强度校验、接口适配 |
| 后端开发 | 验证哈希密码、存储与认证逻辑调整 |
| 运维/DevOps | 环境变量配置、HTTPS、速率限制、监控 |
| 安全团队 | 审查算法与配置 |
| QA | 制定并执行测试计划 |

### 系统设计与架构

#### 密码处理流程

1. 用户输入密码。
2. 前端使用 `SHA256(原始密码 + 固定盐值)` 生成64位十六进制小写字符串。
3. 哈希值通过 HTTPS 发送至后端。
4. 后端在数据库中存储 `Argon2(前端哈希值)`。
5. 登录时比对 Argon2 结果。

#### 环境变量

| 名称 | 说明 | 示例值 |
| --- | --- | --- |
| `VITE_PASSWORD_SALT` | 前端盐值，需与后端一致 | `R3nd@_S3cur3_S@lt_2025` |
| `PASSWORD_SALT` | 后端读取的盐值 | `R3nd@_S3cur3_S@lt_2025` |

#### 安全控制

- 所有密码相关接口仅允许 HTTPS。
- 登录接口速率限制：10次/10分钟/用户+IP。
- 密码重置接口速率限制：5次/小时/用户。

### 测试与验证

- **单元测试**：前端哈希函数、后端密码校验与Argon2存储。
- **集成测试**：模拟注册、登录、重置流程，验证请求格式与响应。
- **安全测试**：中间人攻击模拟、速率限制测试。
- **验收测试**：多浏览器、多平台验证。

### 部署计划

1. 在预发布环境部署前后端代码并配置一致盐值。
2. 验证监控指标是否正常。
3. 灰度发布至部分用户群体。
4. 全量上线并监控异常。

### 回滚策略

- 保留旧版认证服务镜像与配置。
- 启用双模式验证以支持旧客户端。
- 若出现严重故障，切换回旧版并通知用户。

### 风险与缓解

| 风险 | 影响 | 缓解措施 |
| --- | --- | --- |
| 客户端未升级无法登录 | 高 | 提前通知并提供更新指引 |
| 盐值泄露 | 中 | 使用环境变量和密钥管理服务 |
| 新速率限制导致误封 | 低 | 配置白名单并持续监控 |

### 未来工作

- 支持 WebAuthn 等无密码方案。
- 引入多因素认证（MFA）。
- 自动轮换盐值与密钥。
- 提供图形化运维面板。
