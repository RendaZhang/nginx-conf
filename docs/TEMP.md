### **前端需求文档：密码安全传输升级**

#### **目标**
实现前端密码哈希处理，避免原始密码在传输过程中暴露，提升系统整体安全性。

#### **核心需求**
1. **密码哈希处理**
   - 在用户注册、登录、密码重置场景中，对用户输入的原始密码进行哈希处理
   - 哈希算法：SHA-256
   - 哈希格式：64字符的十六进制小写字符串
   - 哈希公式：`SHA256(原始密码 + 固定盐值)`

2. **盐值管理**
   - 通过环境变量获取盐值：`VITE_PASSWORD_SALT`
   - 确保盐值与前端的`PASSWORD_SALT`完全一致

3. **密码强度检查**
   - 在用户输入密码时实时检查强度（无需等待后端验证）
   - 强度规则：
     - 长度 ≥ 8 字符
     - 至少包含以下两类字符：
       - 字母（a-z，A-Z）
       - 数字（0-9）
       - 特殊字符（!@#$%^&*等）
   - 弱密码时阻止表单提交并显示错误提示

4. **接口调用调整**
   - 注册接口（`POST /auth/register`）：
     - 请求体中的`password`字段传递哈希值
   - 登录接口（`POST /auth/login`）：
     - 请求体中的`password`字段传递哈希值
   - 密码重置接口（`POST /auth/password/reset`）：
     - 请求体中的`password`字段传递新密码的哈希值

#### **注意事项**
1. 使用标准加密库（如`crypto-js`），确保哈希结果一致性
2. 所有涉及密码的接口必须使用HTTPS协议
3. 错误处理：
   - 400错误：密码格式错误（需检查哈希实现）
   - 401错误：统一显示"账号或密码错误"
4. 与后端同步部署，不可单独上线

#### **对接验证点**
1. 检查哈希后的密码是否为64位十六进制字符串
2. 使用固定测试值验证前后端哈希结果一致：
   - 原始密码：`Test123!`
   - 盐值：`R3nd@_S3cur3_S@lt_2025`
   - 预期哈希：`a9f5c...`（完整哈希需实际计算）

### **后端需求文档：密码安全传输升级**

#### **目标**
支持接收前端哈希后的密码，并保持现有密码存储机制的安全性。

#### **核心需求**
1. **密码格式验证**
   - 在注册/登录/密码重置接口中验证接收的密码：
     - 长度必须为64字符
     - 格式必须为小写十六进制字符串（正则：`^[a-f0-9]{64}$`）
   - 无效格式返回400错误（错误消息："Invalid password format"）

2. **密码处理逻辑调整**
   - 注册接口（`POST /auth/register`）：
     - 直接存储Argon2(前端哈希值)到数据库
     - 移除原始密码强度检查（由前端负责）
   - 登录接口（`POST /auth/login`）：
     - 直接比对Argon2(前端哈希值)与数据库存储值
     - 统一返回"Invalid credentials"防止账号枚举
   - 密码重置接口（`POST /auth/password/reset`）：
     - 使用Argon2(前端哈希值)更新凭据

3. **环境变量配置**
   - 新增`PASSWORD_SALT`环境变量
   - 值必须与前端的`VITE_PASSWORD_SALT`完全一致

4. **错误处理优化**
   - 登录失败时记录日志（不记录具体密码值）：
     ```log
     [WARNING] Repeated login failures for user@example.com (IP: 192.168.1.1)
     ```
   - 密码格式错误返回400（区分于认证失败的401）

#### **数据迁移方案**
1. **新用户**：直接使用新存储格式（Argon2(SHA256(密码+盐))）
2. **现有用户迁移**：
   - 方案A：强制所有用户在下次登录时重置密码
   - 方案B：过渡期支持双模式验证（按需实现）：
     ```python
     if len(pwd) == 64:  # 新客户端
         verify_hash(pwd)
     else:  # 旧客户端
         legacy_verify(pwd)
     ```

#### **安全要求**
1. 生产环境使用高强度随机盐值（建议32字符）
2. 所有密码相关接口添加严格速率限制：
   - 登录：10次/10分钟/IP+账号
   - 密码重置：5次/小时/账号
3. 响应头强制安全策略：
   ```http
   Strict-Transport-Security: max-age=31536000; includeSubDomains
   X-Content-Type-Options: nosniff
   ```

#### **对接验证点**
1. 测试接收前端哈希后的密码能否通过验证
2. 验证新注册用户凭据存储格式是否正确
3. 确保`PASSWORD_SALT`与前端值完全匹配

### **前后端协同要求**
1. **部署同步**：必须同时上线，否则认证服务将中断
2. **盐值管理**：
   - 预发布环境：`R3nd@_S3cur3_S@lt_2025`
   - 生产环境：使用高强度随机生成值（双方一致）
3. **监控指标**：
   - 前端：密码哈希失败率
   - 后端：400密码格式错误计数
4. **回滚计划**：准备双模式验证代码以便紧急回退

> **重要提示**：此升级将使未更新的客户端无法登录，建议：
> 1. 提前3天通知用户
> 2. 在登录页添加维护公告
> 3. 准备客户端强制更新机制（如版本检测）

通过这份文档，前后端团队可以明确各自职责，并基于标准化的接口规范实现无缝对接。
